# 联机对战实操指南（跨网 / 局域网）

> 适用版本：会话 36 起的协议 v1。双方都要用**同版本**的 `tankwar.exe`
> （协议字段 ver=1 不匹配会当无效包丢弃）。游戏是 32 位 Windows 程序，
> macOS/Linux 无原生构建（Wine 未验证）。

## 一、同一局域网直连（最简）

1. 双方启动游戏 → 主菜单选「**联机大厅**」。
2. 双方各自绑定监听端口：先启动的一方拿固定口 **28888**，
   后启动的一方自动退避到临时口（两边都能互相发现，无需配置）。
3. 大厅显示「已发现对手」后，**双方都按 Enter**（单边按不会开局，防误触）。
4. 开局后两端同图同出生点，直接开打。
5. 走不通时先看第三节（防火墙是局域网联不上的头号原因）。

不想等同伴开游戏再进大厅的，也可以直接进大厅在底部「手动连接」编辑行
输入对方 IP（如 `192.168.1.24` 或 `192.168.1.24:28888`，回车或点连接）——
广播被封的网段（公司/校园网常见）就用这条路。

## 二、跨网（互联网）对战——推荐虚拟局域网

双方都不在同一个网段、且都没有公网 IP 时，游戏自身**无法穿透 NAT**。
最省事的办法是用免费隧道工具把两台电脑拼成一个虚拟局域网，然后
在大厅里输对方的**虚拟 IP**，流程与局域网完全一样。

### 方案 A：ZeroTier（P2P 隧道，推荐）

1. 双方都安装 ZeroTier One，各自 `Join Network` 加入**同一个网络 ID**
   （一方到 my.zerotier.com 免费创建，勾选 Private 即可）。
2. 在控制台把双方设备都 **授权（Auth）**。
3. 各自记下分到的虚拟 IP（`10.x.x.x` 或 `172.x.x.x` 段，ZeroTier 托盘可见）。
4. 一方进大厅，另一方在「手动连接」输它的虚拟 IP，回车。
   - 双方都在大厅时也可以直接互输，谁先输都行；被输的一方不需要任何操作
     （announce 单播会自动"打开"它的入站，它的 reply 再回连）。
5. 双方按 Enter 开局。

### 方案 B：SakuraFrp / n2n 等内网穿透（备选）

适合 ZeroTier 官网/节点被墙掉线的环境：

1. 一方在 frp 服务商建一条 **UDP 隧道**，把自己的 28888 端口映射到公网；
2. 另一方在「手动连接」输 `公网IP:映射端口`；
3. 固定端口映射方建议**先启动游戏**（绑上 28888），穿透映射指到它才稳。

### 通用小技巧

- 同机双开测试也算"跨实例联机"：大厅一方输 `127.0.0.1` 即可（广播+环回
  探测本身就支持同机互发现，`netloop` 自动化验收用的就是这条链路）。
- 端口被占不用管：程序自动退避临时口，发现机制会交换真实端口。

## 三、Windows 防火墙排坑（联不上的头号原因）

现象：大厅永远「搜索中」/ 一方能连另一方连不进 = 入站被系统挡了。

1. **首次启动被 UAC 询问时务必勾选专用+公用 networks**（勾歪了后面手动改）。
2. 手动放行：`控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 →
   更改设置 → 允许其他应用 → 浏览选 tankwar.exe`，**专用和公用两列都打勾**。
3. **公用网络陷阱**：Win10/11 新连的 Wi-Fi/以太网常被识别为「公用网络」，
   默认阻断一切入站 UDP。核对：`设置 → 网络和 Internet → 状态（或该连接）
   → 属性 → 专用`。虚拟网卡（ZeroTier）同样要设为专用。
4. 仍不通时临时**关闭防火墙**验证是不是它的锅（测完记得开回去）；
   或安全软件（360/火绒等）里给 tankwar.exe 放行 UDP。
5. 路由器层：局域网直连不需要任何端口映射；只有 frp 公网方案才涉及服务商
   侧端口分配，家用路由器通常不用动（UDP 单播双向自动打通）。

## 四、连不上的判定流程

大厅里按从近到远逐档排查：

| 步骤 | 操作 | 结果判定 |
|------|------|----------|
| 1 | 同机双开，一方输 `127.0.0.1` | 通 → 程序没问题，往下看；不通 → 版本不对/程序损坏 |
| 2 | 手机热点互连 + 输对方 IP（`ipconfig` 看 192.168.x.x） | 通 → 是原网段封广播/防火墙；不通 → 查双方防火墙档位 |
| 3 | ZeroTier 虚拟 IP 互 ping（`ping 10.x.x.x`） | ping 不通 → 隧道没组好（网络 ID/授权/客户端离线），与游戏无关 |
| 4 | ping 通但游戏连不上 | 查虚拟网卡被识别成「公用网络」（见第三节 3 条） |

### 对称 NAT 判定（为什么不是所有环境都能直连）

`tracert <对端公网IP>` 或打洞测试工具显示两端 NAT 类型都为
**端口限制锥形/对称型（Symmetric）**时，最简打洞（本作的 announce/reply
互补入站）会失败——对称 NAT 给不同目的地址分配不同出口端口，
"我打你一次你就能回我"的前提不成立。此时：

- 首选：走 ZeroTier/SakuraFrp（中继或隧道不依赖打洞）；
- 长期：游戏内嵌 STUN 打洞（列入 **M3.5** 里程碑，未实现——届时大厅
  输入公网 IP 即可直连，无需第三方工具）。

## 五、联机模式玩法差异（已知裁剪）

- **换位术、定格虚影两种道具联机不出现**（两端镜像差会导致永久发散，
  属协议层限制，非 bug；单机模式不受影响）。
- 掉线时画面出现「连接丢失」覆盖层并冻结，对方回来**自动续上**；
  Esc 回大厅也可主动重连。
- 联机中 R 键重开被禁用（各端重洗地图袋会炸同步），回大厅重开局。
