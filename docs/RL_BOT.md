# RL 训练管道（会话47）

目标：训练一个"完全智能"的对战 bot，替代纯规则人机在对抗性上的天花板
（典型症状：玩家原地转圈，启发式 bot 的瞬时朝向判读被姿态噪声喂满，
决策来回振荡——见会话46B 治理记录）。规则侧修补已到收益递减点，
改走"引擎即环境 + PPO 自博弈"路线，最终蒸馏回汇编。

## 架构总览

```
Python (64bit, numpy PPO)
   │  stdin/stdout 定长二进制帧（64B 请求 / 3669B 快照=SNAP3573+电平96）
   ▼
tankwar.exe rlhost ×N 进程          ←── 环境（无头 GameUpdate，零渲染零声音）
   game.asm/bot.asm/input.asm 同一套代码，与正式游戏逐字节同源
```

- 为什么用 exe 管道而不是 DLL：Python 侧只有 64 位解释器，装不了 x86 的
  `tankwar_rl.dll`（ctypes 位宽不兼容）。exe 模式无此约束，还能多进程
  并行=天然多环境采样。DLL 路线（rl.asm/rl_stub.asm/build_rl.bat）保留，
  将来若有 32 位 Python 可无缝切回（帧语义一致）。
- 吞吐实测：单步往返 ~2.4万 ticks/s；rep=20 批步 ~21万 ticks/s；
  PPO 6 进程 ≈ 6千 env-steps/s（Python 前向/观测组装为瓶颈，够训）。

## 协议（src/rlhost.asm 是唯一权威，本节为镜像）

请求恒 64B：

| 偏移 | 字段 | 含义 |
|---|---|---|
| 0 | u8 cmd | 1=RESET 2=STEP 3=PING 4=META |
| 1 | u8 flags | bit0：双手动（botMask=0，自博弈）；bit1：换位（slot0=启发式 bot、slot1=主机，BC 采集用，优先于 bit0）；全 0：slot1=启发式陪练（默认） |
| 4 | u32 aux | RESET: seed（0=时间播种）；STEP: tick 数 0..240 |
| 8 | i32[6] | slot0 电平 F,B,CCW,CW,Fire,Skill（与 inputTable 同通道） |
| 32 | i32[6] | slot1 电平（bit0 或 bit1 时生效） |

应答 SNAP（rlMetaVer≥3，会话47C）：头 14×u32
（magic,gTick,rngMatch,mapIndex,matchOver,roundsPlayed,maxRounds,
pickupType,X,Y,Timer,botMask,rngState,保留），其后 tanks[4]、
bullets[56]、mapData[COLS×ROWS] 原样内存块，**帧尾再拼
inputTable 4槽×6 dword（96B）**——STEP 应答里的电平即"本 tick
实际生效值"（bot 槽由 BotThink 覆写=行为克隆标签）。Python 侧
帧长 = META[0](SNAP_TOTAL) + MAX_PLAYERS*KEY_PER*4，与 rlrec
UDP 帧逐字节同构。

META 帧 64×u32：结构尺寸/区段偏移/地图常量/TANK 29 成员偏移/
BULLET 11 成员偏移/版本。偏移全部运行时从局部假实例算出，TANK/BULLET
加字段后 Python 表自动跟随（tools/rl_env.py 启动断言兜底）。

确定性：`rngSeedOvr`（GameInit 钩子，默认 0 时游戏/自检路径逐字节不变）
+ rlhost 复位时 `gTick=0` 对齐交替速度相位。同 seed 两次 300tick 全轨迹
终态一致（tools/rl_env.py 冒烟2 锁死这一性质）。

## 观测/动作/奖励（tools/rl_train.py）

- OBS=90：ego 11（位姿/血/冷却/技能/护盾/命）+ 敌方 10（相对位置、
  瞬时 sin/cos、**16tick EMA 质心航向**、起瞄、技能）+ 最近 6 弹×6 +
  脚下 5×5 地形 + 道具 4 + 比分/轮次 4。
  转圈对策就在 EMA 质心航向：原地打转的瞬时朝向在特征里被平均掉，
  bot 只能从位移与瞄读里读到意图，姿态噪声失去欺骗力。
- 动作 36 = 走{进,退,停} × 转{逆,顺,停} × 开火 × 技能，解码成 6 电平，
  与真人按键同通道（策略不碰任何后门）。
- 奖励：击杀 +5 / 阵亡 −5 / 回合分 +3（对手拿分 −1）/ 逼近塑形
  ±0.02（仅双方存活）/ 时间 −0.002/tick。回合分在**加分发生的那一
  tick**结算（会话47C 探针 rl_probe47.py 实测：多数回合同 tick 加分+跳变，
  少数先加分、跳变 tick 反而清零 score——旧写法会漏判）；episode 在
  roundsPlayed 跳变/matchOver 切断，胜负=回合内正得分差累计。
- 进度指标：**阵亡比 die0:die1** 比 win% 更抗判定噪声（随机策略≈8:1，
  日志与 EVAL 都打印）。
- **能力显式化（会话47D）**：用户点名四项能力=开火/追踪/技能/躲弹，
  奖励与评估双侧落实。奖励在 kill/death/逼近/时间之外新增四路稠密信号：
  ①躲弹势函数塑形 F=γΦ'−Φ（Φ=−0.6·威胁和，威胁=迎面弹 180px 内按
  距离²衰减，己方弹权重 0.35 防自伤不压开火，单 tick 限幅 0.1）；
  ②技能链（game.inc 查实 skill=持有待发动 SK_ id，引擎消费归零为权威
  发动沿；effOn 全是益己掩码，不可当我方命中信号——第一版归因写反已纠）：
  拾取 +0.6 / 发动 +0.3 / 发动后 40tick 内敌方掉血 +1.0；
  ③锁瞄：双方存活 <430px 且车头偏差 <12° 给 +0.03/tick〔run7 起 0.05：
  run6 实测 0.03 档被躲弹塑形(0.1/tick 限幅)压制，瞄占比仍 1~3%〕，
  出膛 2tick 弹头距敌心 <50px 记"准星弹" +0.5〔run7 改版：age==2 弹头
  只离膛 5px，等价"贴脸 50px 内战"才发，477px 交战距下恒 0=瞄准梯度
  断供——改为自弹**首次进入敌 20px 擦身带**记一次，全程有效、一弹一销〕；
  ④道具趋近塑形 ±0.02〔run7 起 ±0.03，另加**进圈奖**：侵入道具 80px
  圈一次性 +0.4——run6 全程 0 拾取证明纯距离塑形压不住"中心区=弹道
  开阔带"的避险惯性〕。（旧"反放风筝 −0.006/tick"罚项 run3/run4 两次
  实证逼出蛮干，已永久关闭，见上节；技能唯一来源是拾取，不吃道具=技能链
  永闭。）评估侧 `Cap` 能力卡把四项拆成独立读数（开火/千tick、击杀
  〔归因〕+捡漏双轨、中弹、极限躲弹率[擦身 40px 判定]、技能四级漏斗、
  瞄准占比），EVAL 与 rl_server 同口径。run2 实测：躲弹 63%(57/91)
  学成，瞄 3%/技 0 发未学成 → ③④ 即为其对症加强。
- **弹速通道归一**（会话47B 修正）：bullet vx/vy 是 16.16 定点，|v|≡
  BULLET_FP=176947（≈2.7px/tick，game.inc:195）。最初按 /8.0 归一错误
  （通道值 ±2.2万），现由 META[62]/[63] 导出 BULLET_FP/FIX_ONE，Python
  除以 BULLET_FP 得 ±1。旧 match 级权重归档 `rl_policy_matchlevel.npz.bak`。
- PPO：numpy 手推梯度（tools/gradcheck47.py 数值校验 rel<1%），
  2×128 tanh 主干 + 策略/价值头，γ.99 λ.95 clip.2 ent.01 Adam 3e-4。

## 训练与评估

```
python tools/rl_train.py --iters 1000 --envs 6 --steps 384 --opp script  # 默认陪练=进攻脚本
python tools/rl_train.py --eval-only --rounds 60 --opp script            # 贪心回合胜率+阵亡比
python tools/rl_train.py --eval-only --rounds 60 --opp heuristic         # 对真人机强度
```
权重 `rl_policy.npz`，周期快评最优存档 `rl_policy_best.npz`，日志 `rl_train.log`。
会话47C 超参教训：lr 3e-4/4ep 推不动（200 迭代=随机水平）；1e-3/8ep 能学但
后期塌车（0.8M 步见顶 12% 后回落）→ 现行配方 = **1e-3 线性退火至 1/10 +
每 50 迭代贪心快评并存最优**。评估以贪心胜率+阵亡比为准，训练窗 win%
含探索噪声仅作趋势看。

### 陪练对手：从启发式改为进攻脚本（会话47C-2 实锤）
`--opp script`（默认）用 Python 脚本 `script_act` 走 slot1 真人电平通道：
追近 + 死区瞄准（容差 3°，2 倍死区内开火）+ 430px 内射击 + 距离保持。
实测对随机策略 8000 tick 杀 20 自亡 2——信号密度约为启发式的 25 倍。
弃用启发式当陪练的行为学根因：**启发式 bot 对移动/转圈目标几乎不开火
（实测 1~5 弹/6000 tick，两种角色皆然）**——这正是用户报"我原地转圈
人机就发呆"的根源，克隆或陪练它都学不到对抗性。

### 课程对手（会话47D，借鉴 Cal Poly TankGame / BattleCity2021 对抗训练共性）
`--opp-var`：每个 env 每次换局重掷陪练旋钮——死区 2~8°、开火视距
260~470px，6 env 同时挂 6 档难度=天然课程池。单一强度对手会让策略
过拟合到该风格（run2/3 实测不同噪声窗起伏大，与此一致）。
评估不用 --opp-var（固定 3°/430px 标尺，保证跨轮可比）。

### 击杀归因与"装死等自爆"退化矫正（会话47E）
run#5（RUNAWAY 罚关闭后）快评峰值 58%/阵亡 9:18 入 BEST，但能力卡暴露
**虚假繁荣**：两个 58% 档开火仅 0.6/千t（低于启发式的 1.2），击杀 1.15/
千t 与 9 发弹对不上账。查引擎真相三条：
- **反弹自伤是真实机制**：普通弹 age≥2 可命中射手自己（会话30 出膛宽限/
  会话33"恢复普通自伤规则"注释，game.asm TankHitLoop）——脚本陪练火力
  密、贴墙开火，常被自己弹反弹炸死；
- **回合分判"最后存活者"**（game.asm:9379），对面自爆我方白得生存分；
- **成就行只认 dmgSrc≠victim**（game.asm DamageTankRaw"自雷不记 kill"），
  引擎自己都不把自爆算击杀，而旧 kill+5 无归因——对面自爆成了训练里
  最稳收入 → 策略理性退化为"不开火不交战，装死等对面自爆"。
矫正（rl_train.py reward ④E）：伤害 tick **双证归因**才记分——我方弹
在 prev/s 两帧弹池与受害方命中盒重叠（`own_gun_hit`；引擎命中同 tick
销毁子弹，单查 s 池必漏，prev 为主证），或技能发动 40tick 窗口内——
致死 +5，未致死 **+HIT_P 0.8**（新增"打中即赚"稠密信号）；无证据 0 分。
能力卡与 rl_server 同步双轨：**击杀(归因)/捡漏**——冒烟实测旧 BEST 权重
6 回合"杀 0.00(归因)/捡漏 4"，退化第一次被定量指认。躲弹项不受影响
（run5 躲弹 66~81%，四项能力里最扎实的一门）。

run#6（归因奖励首跑）验证矫正有效但揭出下一层：开火从 0.6 恢复到
7~18/千t、快评峰 54%（装死版归档 rl_policy_turtle58.npz，不再参与
BEST 竞争）；然而**击杀(归因)仅 0.06~0.54/千t（命中率 ~3%）、瞄占比
1~3%、技能拾取全程 0**——它猛开火却不瞄准。两条梯度断供根因：
准星弹 age==2 判据形同虚设（弹只离膛 5px，477px 交战距永不触发）+
道具塑形压不住"中心区=开阔弹道带"避险。run#7 三改（见上节〔run7〕
标注）：擦身带准星弹/锁瞄 0.05/道具进圈奖。

run#7 收官：瞄准第一次爬坡（快评档 3~9%、击杀(归因)峰 0.57/千t ≈
命中率翻倍到 ~9%），躲弹 42~77%（更激进所致），快评峰 50% 入 BEST。
技能拾取仍全程 0——**道具切片探针**（tools/item_probe47e.py）判死
病因：最优权重距道具 p10=165px、80px 进圈率 **0.0%**，而技能键按下率
**33%**：有发动意图却从不走向道具，属激励量级问题而非机制问题（旧
系数下趋近塑形仅兑现 0.003/tick ≈ 躲弹塑形的 1/30，梯度被淹没）。
run#8 把道具经济抬到击杀量级：拾取 1.2→**5.0**、进圈 0.4→**2.0**、
发动 0.6→**1.5**、命中窗 1.5→2.0、趋近塑形系数 1.2→20（±0.08/tick）。

run#8 收官给出**判决性反例**：中段确有开火 10~19/千t、归因杀
0.32~0.58/千t、瞄 3~9% 的对拼窗口，但 lr 退火后一路滑回装死，最终
BEST 竟是 **79% 纯装死档**（开火 0.9/千t、捡漏 19、拾取 0）——问题
出在**选拔函数**：只要训练对手会自爆、判据只看胜率，装死就系统性地
收割 BEST；道具经济加到 5.0 也救不了（进圈率仍 0.0%）。run#9 两项
结构改造：
- **混合对手池**（`--opp mix`）：逐 env 对半 script/heuristic，换局
  随机重掷。启发式池不自爆，其回合只有"真打中"才能赢（打不中=平局
  记负），装死收益直接砍半，逼策略长出对真人也成立的战斗技能；
- **复合分选 BEST**：`comp = win% + 100×击杀(归因)/千t + 20×(拾取+
  发动)`——装死档 79+6≈85，对拼档 42+58≈100 起步再加技能分，能力
  产出直接参与"谁是存档点"。`--best0` 同步改 comp 量纲。

run#9 收官判决：选拔函数**生效**—— anneal 后段连续出现 67%/50% 胜率
的 turtle 窗口（开火 0.0/归因杀 0.00），comp 全部拒存（run8 旧口径必存），
留下的存档位是对拼型 comp=92/96（首现拾 1/发 1）。comp=96 双正评：
**vs script 45% / vs heuristic 32%**——双项历史最好（run5 同口径 40%/15%，
run2 28%/22%），躲弹 79%（vs script）稳。但同场暴露 comp 两处缺陷：
正评开火仅 0.4~0.7/千t、探针进圈带 0.1%/拾取带 0.0%——快评"技 1 拾"只是
1/24 回合的幸运事件，而**按次计 20 分**让一次幸运白得 +40，压过一切；
且开火不在选拔维度里，win 4% 但火 11.6/杀 0.65 的真打窗口（comp=69）
被纯运气档挤掉。run#10 口径修正：`comp = win% + 100×归因杀/千t +
3×开火/千t + 100×(拾取+发动)/回合数`——技能项归一化到回合（1 次/24 回合
仅 +4.2），开火率直接入选拔；45/32 现档备份 `rl_policy_45_32run9.bak.npz`
作 warm-start 与对照。

run#10 收官：comp 爬 42→45→55→60→69→**110**，末窗火 8.2/千t、归因杀
0.57/千t（全存档史最高归因）、中弹 1.00/千t——**首个真打手档**。正评
vs script 33%（火 5.1、归因杀 0.35、捡漏 30、躲弹 63%）/ vs heuristic
25%（火 6.0、归因杀 0.45、捡漏 11）：**首次双池开火率都盖过启发式陪练
自己的 1.2~3/千t 且归因击杀成立**（run9 的 45%/32% 靠捡漏，开火 0.4）。
胜率让掉 12/7 个点是"捡分"与"打赢"的本征差，对用户点名的四能力而言
run10 档更对目标。技能漏斗仍 0，探针给出**互斥证据**：道具距离 p10 随
战斗权重上升持续恶化（run7=165 → run9=219 → run10=396px，进圈带恒
≤0.1%）——交战卡距(~400px 火线)与走向道具天然冲突，comp 单档里技能项
永远输给开火项。run#11 对策：**双存档点**——主档 comp 不动；新增
`rl_policy_skbest.npz` 按"技能漏斗产出率 (拾取+发动)/千t"历史最高单独
守档（漏斗开张的档无论 comp 高低都留住），收官后与主档双对照正评，
关闭"技能档在选拔中蒸发"这一观测盲区。

run#11 收官三情报：①**主档又栽在选拔第三缺口**——win-0 狂战档登顶
comp=129（火 14.8=44 分+归因杀 0.84=84 分，die 24:12 每回合先死、0/24
胜），压过 win 38% 的 124 均衡档：杀/火项没有生存约束；②**技能守档
首次把漏斗带进正评**——skbest 档（it100 窗 拾2/发2/中2，sk=0.210/千t）
60 回合正评 **vs script 55%（历史最好，run9 45%）/ vs heuristic 18%**，
能力卡首现 拾取1/发动1（60 回合口径），但开火 0.6 又是捡漏型（die
15:42、躲弹 79%），对启发式脆（18%）；③skbest 探针进圈带 **1.7%**
（历档 0.0~0.1%，17 倍）但 p10=388px、拾取带 0.0%——**趋近仍不成立**，
开张靠守档运气。三档并读（run9 捡分型 45/32、run10 战斗型 33/25、
run11 技能守档型 55/18）把病灶钉死在**趋近与交战卡距互斥**：p10 道具
距离随开火权重单调恶化 165→219→396px，奖励里两条梯度永远反向，
策略只能在三档间摇摆。run#12 双刀：①comp 补生存项
`+100×(敌亡−己亡)/回合数`（狂战档 -50→78 出局，被动档直接负分）；
②**威胁门控趋近塑形**——同 tick 弹威胁上升时正向趋近分清零（负项
不门控，退道具恒罚），把"抢道具"逼成火线切线走位，与躲弹梯度同向
而非对冲。run#10 战斗档（rl_policy_10combat.bak.npz）warm-start。

run#12 收官——双刀各验各的，但挖出更深的账本病。刀①（生存 comp）**生效**：

### 行为克隆（BC）工具与定论
`rl_bc.py` 用**换位标志 flags.bit1**（slot0=启发式 bot、slot1=主机）逐 tick
采 (ego=slot1 观测, 帧尾 inputTable[0..5] 的 bot 电平→36 动作下标)。
**对启发式做 BC 已实测放弃**：它的标签本身几乎不含开火（见上节 1~5 弹/6000
tick），克隆出来的只会是"跟着转圈发呆"——与用户要治的毛病同源。
但协议层面的收获保留：BotThink 在 tick t 基于 state(t−1) 写电平并同 tick
执行，**正确配对 = obs(t−1) ↔ lv(t)**（出生 tick 实测锁死）；帧尾电平区是
保留通道非脉冲。工具链（采集/CE 拟合/`.pre_bc.bak` 备份）原样保留，
将来喂 **真人 rlrec 对局数据**（见下节）做 BC 时直接复用。

> 会话47 修订：episode 从"整场"改为"一回合"（roundsPlayed 变化即切断）。
> 比赛级实测 2.8M 步只切出 ~500 局、win 恒 0/N——双方无限复活互耗，局几乎
> 不终结，advantage 信噪比过低。回合级后每 256 步窗口就能出 1~2 个终局样本。

## Phase3 蒸馏（会话47E-48 完成）

原"int16 定点"方案作废：x87 float32 直算足够快（90→128→128→36 约
25K MAC/tick，60fps 预算零压力），且免量化误差。落地四件套：

**① src/rlbot.asm（NN 推理模块，~960 行纯 asm）**
- 权重由 `tools/gen_rlbot_data.py` 从 `rl_policy_14champ.bak.npz`
  （run14 冠军，md5 e0048ff85e34a2ce706307800e26db46）逐位落成
  `inc/rlw.inc`：float32 位模式 `0XXXXXXXXh` 字面量（ml 不认 0x 前缀），
  三矩阵转置成 [out][in] 行主序供内层顺序读。
- tanh 用 4097 点线性插值表（x∈[-8,8]，步长 2⁻¹¹，最大误差 ~1e-6）。
- 三角函数直接查引擎 cosTBL/sinTBL（×1/1024）——与物理层同盘绕度。
- 决策段 `fldcw 0F7Fh`（RC=向零截断）出入各保存/恢复一次，与 python
  float→int 截断语义对齐；`fnstsw ah` 在 ml 下非法且会污染 eax 高位，
  一律 `fnstsw word` + `test,0100h/4100h`。
- `RlBotThink(pSlot)`：六通道清零 → RlBuildObs（90 列，与
  tools/rl_train.py build_obs 逐式对应）→ alive 门 → RlForward →
  raw 快照 → RlBeacon → RlChoose（argmax 写 0/1 电平进 inputTable，
  通道= fwd/back/ccw/cw/fire/skill）。

**② 道具信标叠加层（关"技能几何冲突"）**：16 轮 RL 终判趋近道具与
交战卡距是策略几何问题，纯权重学不会——蒸馏侧改用运行时 logits 偏置：
道具在场 & 40<d<700 & 260px 内迎面敌弹 ≤ RL_B_THREAT(1) 时，按距离带
w=1.0/0.6/0.3 给"车头能转过去/能直行接近"的 9 组 mv×tn 动作加
w·(RL_BKM·dotN + RL_BKT·crsN)（常量烤进 rlw.inc，RL_BKM=1.2 RL_BKT=0.6，
与 tools/rl_beacon_probe.py beacon_bonus 逐式同构，只含 mul/add/fsqrt）。

**③ 接线**：bot.asm BotThink 分派 `bt rlBotMask` 位**自驱动**（不依赖
botMask——换局 `mov botMask,1 shl BOT_SLOT` 不会抹掉 NN）；game.asm 四处
BOT_* 数值豁免（speed/turn/fireCd/lives，`bt rlBotMask,jc skip`）让 NN 槽
吃玩家物理=训练谱系待遇；main.asm 双入口：GUI `tankwar rlbot [rlbotdump]`
直开人机局 NN 接管 slot0，训练管 `tankwar rlhost rlbot [rlbotdump]` 在
RL 管道内启用 NN（对拍专用）。
- **会话47E 顺手修掉一颗老雷**：start 的 rlhost 扫描原 `mov ecx,7` 含串尾
  NUL——等价"rlhost 必须是最后一个词"，后接任何参数即永不命中、静默落穿
  GUI 消息循环（曾被误读为"NN 在管道里崩/挂"）。改 6 字符子串匹配。

**④ 对拍三件套（tools/）**
- `rl_distill_check.py`：解析 rlbotdump 664B/记录
  ([4i slot,tick,chosen,bkThr][90f obs][36f raw][36f post])，npz 影子复算
  ——A) argmax(post)==chosen、B) NN 前向一致率、C) 信标重构偏置。
  GUI/管道实测 **A=B=C=100%，max|Δraw|≈3e-5**（截断 CW+LUT 噪声，无害）。
- `rl_obs_dist.py`：exe obs 逐列分布 vs 环境贪心 obs 分布（粗对拍，

- `rl_obs_pipe_check.py`：**决定性同 tick 对拍**——管道里 exe 自决策
