# 联机对战实操指南（跨网 / 局域网）

> 适用版本：会话 36 起的协议 v1（会话 37 增中继，v1.1）。双方都要用**同版本**
> 的 `tankwar.exe`（协议字段 ver=1 不匹配会当无效包丢弃）。游戏是 32 位
> Windows 程序，macOS/Linux 无原生构建（Wine 未验证；中继服务器则全平台）。

## 一、同一局域网直连（最简）

1. 双方启动游戏 → 主菜单选「**联机大厅**」。
2. 双方各自绑定监听端口：先启动的一方拿固定口 **28888**，
   后启动的一方自动退避到临时口（两边都能互相发现，无需配置）。
3. 大厅显示「已发现对手」后，**双方都按 Enter**（单边按不会开局，防误触）。
4. 开局后两端同图同出生点，直接开打。
5. 走不通时先看第三节（防火墙是局域网联不上的头号原因）。

不想等同伴开游戏再进大厅的，也可以直接进大厅在底部「手动连接」编辑行
输入对方 IP（如 `192.168.1.24` 或 `192.168.1.24:28888`，回车或点连接）——
广播被封的网段（公司/校园网常见）就用这条路。

## 二、跨网（互联网）对战——推荐虚拟局域网

双方都不在同一个网段、且都没有公网 IP 时，游戏自身**无法穿透 NAT**。
最省事的办法是用免费隧道工具把两台电脑拼成一个虚拟局域网，然后
在大厅里输对方的**虚拟 IP**，流程与局域网完全一样。

### 方案 A：ZeroTier（P2P 隧道，推荐）

1. 双方都安装 ZeroTier One，各自 `Join Network` 加入**同一个网络 ID**
   （一方到 my.zerotier.com 免费创建，勾选 Private 即可）。
2. 在控制台把双方设备都 **授权（Auth）**。
3. 各自记下分到的虚拟 IP（`10.x.x.x` 或 `172.x.x.x` 段，ZeroTier 托盘可见）。
4. 一方进大厅，另一方在「手动连接」输它的虚拟 IP，回车。
   - 双方都在大厅时也可以直接互输，谁先输都行；被输的一方不需要任何操作
     （announce 单播会自动"打开"它的入站，它的 reply 再回连）。
5. 双方按 Enter 开局。

### 方案 B：SakuraFrp / n2n 等内网穿透（备选）

适合 ZeroTier 官网/节点被墙掉线的环境：

1. 一方在 frp 服务商建一条 **UDP 隧道**，把自己的 28888 端口映射到公网；
2. 另一方在「手动连接」输 `公网IP:映射端口`；
3. 固定端口映射方建议**先启动游戏**（绑上 28888），穿透映射指到它才稳。

### 方案 C：自建 UDP 中继服务器（会话 37，跨任意 NAT 含对称 NAT）

不装任何第三方工具：有一台带公网 IP 的机器（VPS/家里做端口映射的路由器/
甚至一方自己的电脑）跑 `relay_server`，双方都只跟服务器单播，游戏报文
逐字节透传。**代价=延迟多一跳；好处=无需打洞、无需隧道，对称 NAT 也能连。**

**编译服务器**（源码 `server/relay_server.c`，单文件）：

- Windows：项目根目录跑 `build_server.bat` → 得 `relay_server.exe`
- Linux VPS：`gcc -O2 -o relay_server server/relay_server.c`（一行，无依赖）

**启动**：`relay_server [端口]`（默认 **28900**，UDP）。防火墙/安全组放行
该端口 **UDP 入站**；家用路由器需做一条 UDP 端口映射到跑服务器的机器。

**双方连接**：各自进「联机大厅」，在底部输入行敲

```
服务器IP:28900#房间号        例  203.0.113.7:28900#4242
服务器IP#房间号              （省略端口=用默认 28900）
```

回车即发 JOIN 入房：大厅显示 `RELAY 4242` + 状态词（等待另一人=**WAITING
PEER JOIN**，两人齐=**PEER PAIRED** 之后互按 Enter 正常开局；第三人进同一
房间=**ROOM FULL** 且不会打扰已配对的两名）。同一服务器上不同房间号互不
相通，可多人各开各的对战。命令行 `netrelay "IP#房间"` 可免手输（自动化
验收 `tools/relay_loopback_test.py` 用的这条）。

> 房间号 1..999999 任意，两名玩家约好一致即可；服务器按"最早入房的两名"
> 配对，掉线 10 秒槽位自动回收，另一方原地重连即可。

**公网观测点显示（会话 51，STUN 步A）**：配对后大厅在 `RELAY 房间号` 下方多
一行小字 `STUN x.x.x.x:port`——那是服务器看到的**对方电脑**的公网出口地址。
它有两层用法：① 对照双方 `ipconfig`/路由器 WAN 口，一眼看出是不是对称 NAT、
出口是否同一台路由器（NAT 类型自查）；② 想免中继试直连时，双方把各自的这
行地址抄给对方，在「手动连接」行输入 `那串IP:端口` 回车——直连能通就甩掉
服务器一跳延迟；不通（对称 NAT 必不通）再回 `IP#房间` 走中继。自动"直连
升级"（STUN 步B：验证可达后无缝改道、失败回落）尚未实现，留作后续里程碑。

### 通用小技巧

- 同机双开测试也算"跨实例联机"：大厅一方输 `127.0.0.1` 即可（广播+环回
  探测本身就支持同机互发现，`netloop` 自动化验收用的就是这条链路）。
- 端口被占不用管：程序自动退避临时口，发现机制会交换真实端口。

## 三、Windows 防火墙排坑（联不上的头号原因）

现象：大厅永远「搜索中」/ 一方能连另一方连不进 = 入站被系统挡了。

1. **首次启动被 UAC 询问时务必勾选专用+公用 networks**（勾歪了后面手动改）。
2. 手动放行：`控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 →
   更改设置 → 允许其他应用 → 浏览选 tankwar.exe`，**专用和公用两列都打勾**。
3. **公用网络陷阱**：Win10/11 新连的 Wi-Fi/以太网常被识别为「公用网络」，
   默认阻断一切入站 UDP。核对：`设置 → 网络和 Internet → 状态（或该连接）
   → 属性 → 专用`。虚拟网卡（ZeroTier）同样要设为专用。
4. 仍不通时临时**关闭防火墙**验证是不是它的锅（测完记得开回去）；
   或安全软件（360/火绒等）里给 tankwar.exe 放行 UDP。
5. 路由器层：局域网直连不需要任何端口映射；只有 frp 公网方案才涉及服务商
   侧端口分配，家用路由器通常不用动（UDP 单播双向自动打通）。

## 四、连不上的判定流程

大厅里按从近到远逐档排查：

| 步骤 | 操作 | 结果判定 |
|------|------|----------|
| 1 | 同机双开，一方输 `127.0.0.1` | 通 → 程序没问题，往下看；不通 → 版本不对/程序损坏 |
| 2 | 手机热点互连 + 输对方 IP（`ipconfig` 看 192.168.x.x） | 通 → 是原网段封广播/防火墙；不通 → 查双方防火墙档位 |
| 3 | ZeroTier 虚拟 IP 互 ping（`ping 10.x.x.x`） | ping 不通 → 隧道没组好（网络 ID/授权/客户端离线），与游戏无关 |
| 4 | ping 通但游戏连不上 | 查虚拟网卡被识别成「公用网络」（见第三节 3 条） |

### 对称 NAT 判定（为什么不是所有环境都能直连）

`tracert <对端公网IP>` 或打洞测试工具显示两端 NAT 类型都为
**端口限制锥形/对称型（Symmetric）**时，最简打洞（本作的 announce/reply
互补入站）会失败——对称 NAT 给不同目的地址分配不同出口端口，
"我打你一次你就能回我"的前提不成立。此时：

- 首选：走 ZeroTier/SakuraFrp（中继或隧道不依赖打洞）；
- **已实现（会话 37）**：自建 UDP 中继 `relay_server`（上文方案 C），
  大厅输 `服务器IP:28900#房间` 即连，任意 NAT 类型无关紧要；
- **已实现（会话 51，STUN 步A）**：中继配对后大厅显示 `STUN ip:port`
  对端公网观测点（服务器反射），可据此手输地址试直连、自查 NAT 类型；
- 内嵌 STUN **步B**（免服务器自动直连升级：打洞探测+双向验证后改道、
  失败自动回落中继）仍留作后续里程碑。

## 五、联机模式玩法差异（已知裁剪）

- **换位术、定格虚影两种道具联机不出现**（两端镜像差会导致永久发散，
  属协议层限制，非 bug；单机模式不受影响）。若因旧档遗留拿到这两种道具，
  按技能键会弹「联机模式不支持该技能」提示条（2 秒自隐，道具同时被吞掉），
  不再是无声无息按了没反应（会话 39）。
- 偶发丢 1~3 个 UDP 包时，对方坦克不再"卡顿定格"，而是按最近速度**惯性外推**
  （每档衰减一半，最多 3 tick），下一包到达即被真实位置纠偏；连续断流仍按
  掉线覆盖层处理（会话 39）。
- 掉线时画面出现「连接丢失」覆盖层并冻结，对方回来**自动续上**；
  Esc 回大厅也可主动重连。
- 联机中 R 键重开被禁用（各端重洗地图袋会炸同步），回大厅重开局。

## 六、联测清单（双机逐项打勾）

验收口径 = 会话36 协议 v1 + 回归套件 `tools/net_loopback_test2.py` 的同
场景实物版。每台机器：防火墙按第三节过一遍，双方版本 exe 必须同构建。

### 局域网双机

| # | 操作 | 通过标准 | 不通先查 |
|---|------|----------|----------|
| 1 | 双方开 `tankwar` 进大厅（联机菜单） | 大厅列表 2s 内互见对方机名/IP | 第三节防火墙；路由器是否隔离广播（改手输 `对方IP` 回车验证） |
| 2 | 各自按 Enter（双 Enter 握手） | 双方同时开局，**地图障碍布局逐格相同、双方出生点镜像交换** | 若图不同=握手种子分叉，记双方 lobbySeed 报上游 |
| 3 | 一方开车转圈，另一方盯屏幕 | 对端坦克位置/朝向平滑跟随（卡顿=丢包，正常自愈） | — |
| 4 | 双方各开几炮、互射 | 弹道两端可见；被打中掉血、死亡爆花在两侧都出现 | 无伤害弹=flags bit1 死亡权威回归，dump 对账 |
| 5 | 技能互放：冰盾/穿墙/氮气/驭水 | 对端能看到盾光、穿墙轨迹、加速尾焰、水带铺地 | 效果只在自己侧=effOn/skill 镜像断，记 tick 号 |
| 6 | 地雷 + 激光（拾取后放） | 雷出现在对侧雷池非己方脚下；激光起瞄虚线对端可见、发射折线两端一致 | 雷落错边/激光无双预览=EVT 去重疑点 |
| 7 | 一方 Alt+F4 强杀进程 | 另一方 ≤2s 出「连接丢失」覆盖层冻结 | — |
| 8 | 被杀方重启并进大厅重连 | 覆盖层一包自愈消失，回到同局继续 | 续不上=掉线 120tick 弹层路径，记 seq |
| 9 | 存活方 Esc 回大厅再重开 | 新一局双方同图同出生点重握手 | — |

### 跨网终验（ZeroTier）

1. 双方装 ZeroTier 组网、互 `ping 10.x.x.x` 通（不通=隧道问题，第四节 3 步，先别动游戏）。
2. 各自 `ipconfig` 取本机 ZeroTier 虚拟 IP，大厅编辑行互输（如 `10.42.x.x`，端口默认 28888，被 LSP 换临时口则不填端口靠反向发现）。
3. 上表 2~9 全程重跑一遍；重点观察 RTT 显示（握手行）与跨公网丢包率。
4. 双方 `tracert 对端公网IP` 若任一端为对称 NAT ⇒ 直连打洞预期失败，改走中继 `服务器IP:28900#房间` 重跑上表（中继路径协议零改动，同一清单）。
5. 中继重跑时加验 STUN 步A（会话 51）：配对后大厅出现 `STUN ip:port` 行，
   且**本机显示的正是对方**自报的公网出口（互报一遍核对）；照方案 C 用法
   双方互手输该地址试一发直连——通=可脱中继，不通=维持中继，均算通过。

### 记录方式

异常时保留两侧 `netdump` 首行（大厅 H 行）+ 出问题那一分钟的 T 行即可
对账（格式见 PROTOCOL.md 末节），不必整局录制。
