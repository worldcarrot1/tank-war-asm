# 网络协议设计（v0）

> 注（2026-10-16）：命中判定取消 owner 豁免 —— 反弹弹可击毁任何坦克
> （包括发射者自己），出弹点移至炮口（坦克边缘外）。此为对战核心规则。
>
> 注（M1）：BULLET 结构已改为弹道向量模型 —— `x/y/vx/vy/owner/active/
> bounces/age`（32 字节），反弹 = 对应轴速度分量取反。NET_PKT 本身未变，
> slot 化扩展（tlvl/tpow/事件字节/地形事件重发）在 M3 落地时同步本文件。

## 基本设定

| 项 | 值 |
|----|----|
| 传输 | UDP，无连接 |
| 拓扑 | P2P，两客户端直连，无服务器 |
| 端口 | 28888（双方相同，bind INADDR_ANY） |
| 发包节奏 | 每个逻辑 tick 一次（约 60Hz，卡顿时可降到 30Hz） |
| 同步模型 | 状态同步：只同步「结果状态」，不同步「输入」 |

## 为什么选状态同步而不是帧同步

- 帧同步要求两端逻辑完全确定（同一输入序列 -> 同一结果），
  汇编下任何浮点/随机/RNG 差异都会造成两边画面分叉，调试极其痛苦
- 状态同步只需要把「我现在的位置/朝向/血量」发给对方，
  对方直接显示。逻辑各自跑，容错好，实现量小一个数量级
- 坦克大战状态量小（一辆坦克 + 开火事件），状态同步绰绰有余

## 状态包格式（NET_PKT，16 字节定长）

```
偏移  大小  字段      说明
0     2    magic     标识 0x5457 ('TW')，过滤无效包
2     2    seq       发送序号，接收端只接受比已见 seq 更大的包
4     2    tx        本端坦克 x（像素，取低 16 位足够）
6     2    ty        本端坦克 y
8     1    tdir      朝向角度量化值 0..255（会话 19 起：本地 dir 为整数度数
                      0..359，0=+x、顺时针为正；发送 q=dir*256/360，
                      接收端还原 dir=(q*360+128)>>8，往返误差 ≤1 度）
9     1    thp       血量
10    1    flags     bit0 = 本 tick 开火
11    1    pad       对齐填充
12    4    (预留)    后续可扩展为子弹方向等
```

小端序，字段全部整数，汇编里直接 `movzx`/`mov` 搬运，无需序列化库。

## 开火事件的处理

开火不单独发包，复用状态包的 flags bit0：
- 本地开火 -> 本地 SpawnBullet + 置 flags
- 对方收到 flags bit0=1 -> 先把包里的 tdir 还原为角度度数写入本地 dir，
  再用 tx/ty/tdir 在本地 SpawnBullet（SpawnBullet 读的就是还原后的 dir，
  所以开火方向以发包瞬间的量化角度为准）

因为子弹速度固定、双方 60Hz 各自演算，几秒内漂移可接受；
阶段 4 若肉眼可见不同步，再让开火包携带子弹初始坐标。

## 命中判定（权威约定）

子弹命中谁，由**被击中一方**本地判定：
- A 的子弹飞到 B 的坦克上 -> B 判定命中，B 自己扣血，hp 随状态包广播
- 好处：不需要额外的命中事件包，链路最简单
- 代价：被击中方掉线时对方打不中它 —— 可接受

## 联机建立流程（阶段 3 实现）

1. 双方启动程序，bind 28888，进入「等待」画面
2. 一方手输对方 IP（阶段 3 早期），或直接 UDP 广播探测（阶段 3 后期）
3. 收到对方第一个合法包 -> 记录对方地址到 peerAddr，进入对战
4. 之后 2 秒无包 -> 判定掉线，回到等待画面
